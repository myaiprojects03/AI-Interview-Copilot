## Write a function that reverses a linked list.

`technical` · first token 657 ms · 95 words · ✅

Sure, here's a simple linked‑list reversal function.

- Create a new head pointer initialized to nil.  
- Iterate through the list, re‑link each node's `next` to the previous node.  
- Advance the current pointer while preserving the original `next`.  
- Return the new head when the original list is exhausted.  
- This pattern is what I used when refactoring data‑structures in our Go payment‑routing service at Brightlane.

```go
type Node struct {
    Val  int
    Next *Node
}

func reverseList(head *Node) *Node {
    var prev *Node
    cur := head
    for cur != nil {
        nxt := cur.Next
        cur.Next = prev
        prev = cur
        cur = nxt
    }
    return prev
}
```

## Can you write a SQL query to find the second highest salary?

`technical` · first token 602 ms · 79 words · ✅

The second highest salary can be retrieved with a window function that ranks salaries in descending order.

- Use `ROW_NUMBER()` or `DENSE_RANK()` over `salary` ordered descending.  
- Filter the result to the row where the rank equals 2.  
- Ensure you select only distinct employee rows if duplicates exist.  
- Works on PostgreSQL, which I use daily for production services.  

```sql
SELECT employee_id, salary
FROM (
    SELECT employee_id,
           salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
) sub
WHERE rnk = 2;
```

## What's the difference between a process and a thread?

`technical` · first token 493 ms · 117 words · ✅

A process is an independent execution unit with its own memory space, while a thread shares the process’s memory and resources.

- Processes have separate address spaces, so a crash in one doesn’t affect others.  
- Threads run within a single process, enabling fast communication via shared memory.  
- Context switching is heavier for processes than for threads, impacting latency.  
- In Go, goroutines map to lightweight threads, which is why I could rebuild the payment‑routing service with low p99 latency.  
- Managing concurrency safely often involves synchronization primitives like mutexes or channels.

## Explain how database indexing works.

`technical` · first token 519 ms · 141 words · ✅

Database indexing creates auxiliary data structures that let the DB locate rows without scanning the whole table.  

- Indexes store sorted copies of one or more columns, enabling O(log n) lookups instead of full table scans.  
- The DB engine uses the index to quickly filter rows, then fetches the full record via the primary key or row pointer.  
- Types include B‑tree for range queries, hash for equality, and GiST for full‑text or geometric data.  
- Maintaining indexes adds write overhead, so you balance read performance against insert/update cost.
